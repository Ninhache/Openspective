# Moderation — design & findings

How openspective moderates short fields (usernames, slugs, build names) and free text
(bios, notes), and *why* it's built this way. Every decision below was validated against
a real dataset (32,926 usernames + build names); the numbers are reproducible.

## TL;DR

```
text ─┬─► lexicon (deterministic, multilingual)   ──► block 1.0  /  flag 0.6
      └─► ML (Detoxify, contextual)                ──► graded score
                          │
            score = max(lexicon, ml)  ──►  >= 0.9 block · >= 0.5 flag · else allow
```

- **Lexicon does ~95% of the real work** — it is precise, instant, language-agnostic, and
  catches literal profanity/slurs in FR/EN/ES/PT. Tiered (slur vs swear) and
  **context-aware**: swears block in usernames but are colloquially fine in build notes.
- **ML is a secondary, contextual net** — it catches a *neutral word used as an insult*
  ("that build is so gay" → high, "it's fucked up" → low) that no word list can.
- Output is **one severity score** mapped to **allow / flag (review) / block**.

On the full dataset: **11 / 32,926 items non-allow (0.03%), zero false positives.**

## The lexicon (primary)

Tiered text files loaded from `OPENSPECTIVE_LEXICON_DIR` (or the bundled seed). Matching:
whole-token by default, `*` opts a term into substring matching, **accents folded**
(`pédé` == `pede`). "Static" means *deterministic*, not frozen — grow the files via the
review loop, no redeploy.

Four tiers, because not all bad words are equal:

| tier | examples | behaviour |
|---|---|---|
| **block** | slurs & person-directed insults — `bamboula`, `salope`, `pute`, `daesh` | blocks **everywhere** |
| **swear** | generic profanity — `fuck`, `shit`, `putain`, `mierda`, `caralho` | blocks only in **strict** (identity) contexts; left to the ML in free text |
| **flag** | borderline — `tamere` | → `flag` (human review) |
| **allow** | Wakfu vocab — `zob`, class names | never matches |

**Context-aware** (`/moderate`'s `context`): `username`/`slug` are *strict* — a swear like
`fuckankama` can't be a name. Free text (`notes`/`bio`/`build_name`) is *lenient* — a
colloquial swear (`it's fucked up` → ML ~0.1, allow) passes, but targeted abuse
(`fuck you` → ML ~0.95, block) is caught by the ML. **Mild** words (`stupid`, `suck`,
`damn`) aren't in the lexicon at all — they're fine colloquially and the ML scores
targeted use. Slurs ignore context: a slur is a slur.

For Wakfuli it is generated by `scripts/build_lexicon.py` from Ankama's in-game censor
dump + LDNOOBW, with these rules (learned empirically — the raw dump over-blocks badly):

| rule | why |
|---|---|
| `censorType` 0/1 → **block** | chat-forbidden = real profanity |
| `censorType` 2 → block **only if also in LDNOOBW** | type-2 mixes slurs (`bamboula`) with game vocab (`support`, `astrub`, class names); the cross-ref keeps the slurs, drops the vocab |
| `m_language` 7 → **drop** | Ankama's spam/URL/RMT bucket (TLDs, `test`, numbers) — flooded FPs (`.com` hit every email) |
| **block always beats allow** | a word in both tiers (e.g. `fuck`) must block |
| stoplist for cross-language FPs | `con`=ES "with", `tit`→FR "p'tit", etc. |

The Ankama dump is **not** committed — it stays local; the repo ships only the generic
multilingual seed.

## The ML layer (secondary) — what we learned

Detoxify is a general toxicity model; several attributes are noisy for this domain:

- **`TOXICITY` dropped** — fires on game combat jargon (`nuke the boss`, `kill stuff` →
  0.6–0.8). Flooded build text with FPs.
- **`OBSCENE` dropped** — fires on gibberish (`Testkckcceck`) and innocent names
  (`One Punch`), double-counts profanity the lexicon already handles.
- **Kept: `INSULT`, `IDENTITY_ATTACK`, `THREAT`, `SEVERE_TOXICITY`** — target-directed
  signals that separate real abuse from game language cleanly.

Identity terms (`gay`, `lesbian`, `trans`) are **never** hard-listed — both Ankama and
LDNOOBW exclude them. The ML grades *usage* instead (`i'm gay and proud` → 0.02 allow;
`that build is so gay` → 0.74 flag). The real anti-LGBTQ **slurs** are in the lexicon.

### Why not the `multilingual` model?

Measured: it **misses** contextual FR/ES insults (`idiotas` 0.16, `gros nul` 0.13) **and**
false-positives on FR/ES gaming (`matar`/`tuer` = "kill" → THREAT ~0.7). Worse on both
fronts than English `original` + the multilingual lexicon. Not used.

### Why not a model per language?

Language detection is unreliable on short strings (the main fields), generic per-language
models share the same gaming domain-mismatch, and it's 4× the memory/maintenance. Not worth it.

## The real next step: one fine-tuned model

Off-the-shelf models can't do *contextual multilingual + gaming domain*. The fix is a
single model fine-tuned on Wakfuli data (covers the languages **and** the domain at once),
loaded via `OPENSPECTIVE_MODEL=/path/to.ckpt`. It needs labels we don't have yet
(~20 today). **The moderation loop generates them**: every `/moderate` decision a
moderator confirms is a training label. Mass-labeling (e.g. user micro-surveys) would
accelerate it. Until then: lexicon + conservative English ML carries it.

## Configuration

| env var | default | role |
|---|---|---|
| `OPENSPECTIVE_LEXICON_DIR` | bundled seed | tiered lexicon directory |
| `OPENSPECTIVE_MODEL` | `multilingual` | Detoxify variant or checkpoint path |
| `OPENSPECTIVE_MODERATE_FLAG_THRESHOLD` | `0.5` | score ≥ → flag (review) |
| `OPENSPECTIVE_MODERATE_BLOCK_THRESHOLD` | `0.9` | score ≥ → block |
| `OPENSPECTIVE_MODERATE_ML_MIN_CHARS` | `12` | min length to run ML (0 = lexicon-only) |

`POST /v1/moderate {text, context?}` → `{decision, score, tier, reasons, mlScore?}`.
